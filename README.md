**현재 진행 단계: 8단계 — 자료마다 갈 수 있는 구역을 나눕니다**

### 이번 단계에서 추가한 내용
- 자원 구분: 기존 메모는 `memo:<자료 ID>`, 공지는 `announcement:<자료 ID>`로 표시합니다. 응답의 `resourceId`와 `X-Resource-ID`로 서버에서 구분합니다.
- 판정기: 기존 기기·추가 확인 규칙을 유지하고 `resource_zones`를 추가했습니다. 서버 관리 정책으로 가명 사용자·기기·반·프로젝트·메서드·정확한 자원 경로를 확인하고 알 수 없는 구역은 거부합니다.
- 최종 API: 검증된 로그인과 저장된 메모 소유자를 조회·수정에서 재검증합니다. 공지 수정은 서버 관리 테이블의 강사만 허용하며 본문 role/owner는 권한으로 쓰지 않습니다.
- 기존 주소와 화면 메뉴는 보존했습니다. 단건 API를 우회하던 광범위한 URL 재작성을 제거하고 쿼리 기능 선택·export·경로 이동·모호한 자료 ID를 거부합니다.
- 단계 설정은 8이며 공지 경로를 추가했습니다. 운영 DB 테이블 적용·엔진 소유자/강사 연결·거부 이유 코드 등록 확인은 미실행입니다. 자세한 준비 내용은 `docs/RESOURCE_ZONES.md`에 기록했습니다.

## 진행 단계 및 현황 기록

### 8단계 저장점 — 자료마다 갈 수 있는 구역을 나눕니다
- 인수 시 README의 7단계 기록과 마지막 커밋 `835778d`의 `7단계 저장점`이 일치했습니다. 다른 XDR 미커밋 작업은 보존합니다.
- 메모 목록·생성 및 단건 읽기 주소를 유지하면서 자기 메모 PUT/PATCH 수정을 지원합니다. `owner_id`는 로그인으로 확인한 사용자 및 저장된 자료와 비교하고 소유자 변경을 받지 않습니다.
- 공지 목록/단건 API를 별도로 추가했습니다. 학생은 로그인 후 공지를 읽을 수 있지만 수정·생성은 DB의 `resource_roles`에서 확인한 강사만 가능합니다. 메뉴는 바꾸지 않았습니다.
- 엔진 계약에는 소유자와 강사 역할이 없으므로 요청 필드를 새로 만들지 않았습니다. `resource-policy.json`은 기존 가상 반/프로젝트의 시험 데이터만 담습니다. 서버 전용 `ALEPH_RESOURCE_POLICY_JSON`의 명시적 운영 정책과 등록된 구역 제한은 유지합니다. 기본 환경의 정상 메모 경로는 시험용 ID에 종속시키지 않고 최종 API의 실제 DB 소유자 검사로 넘깁니다.
- 자원 거부 이유는 `resource_forbidden`입니다. 운영 `allowedReasonCodes` 등록부가 저장소에 없어 등록 확인은 별도로 필요합니다. 실제 심판 통과로 보고하지 않습니다.
- 공지·강사 테이블 준비 SQL은 `docs/RESOURCE_ZONES.sql`에 있으며 기존 메모 데이터를 변경하지 않습니다. 실제 DB에는 아직 실행하지 않았습니다. 자료실 배포 주소·로그인 발급자·기존 허용 경로·원본 API는 유지했습니다.
- 확인 결과: `npm run decider:test`, `npm run fixture:7`, `npm run test:8`을 실제 실행해 통과했습니다. 회귀 및 구역/API 테스트 12개 통과, 실패 0개입니다. 서버 정책·DB를 대체한 가상 시험으로 실제 심판 판정과 구분합니다.

### 3단계 진행 현황 (진짜 로그인을 붙입니다)
- **Supabase Auth 연동**: 이메일/비밀번호 기반 로그인/로그아웃 구현
- **인증 토큰 검증**: `src/verify-login.mjs` 검증 규격 준수 및 API 토큰 수신 검증 (`identityProvider` 설정 완료)
- **가상 메모 CRUD API (`/api/memos`)**:
  - `POST /api/memos`: 메모 추가 (`owner_id` 할당, UUID 자동 생성)
  - `GET /api/memos`: 로그인 사용자의 메모 목록 반환 (미인증 시 401 JSON 반환)
  - `GET /api/memos/:id`: 단건 메모 조회 (삭제 후 404)
  - `PUT /api/memos/:id`: 메모 수정
