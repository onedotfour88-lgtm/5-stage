## 5. 모의·시연과 실제 연결의 구분

- 실제 시스템 연결(SDP, AI 게이트웨이, ALEPH 계정, 실제 OSV, 조치 집행) 성공은 **하나도 확인하지 못했습니다.**
- 확인한 것은 로컬 서버가 정적 파일을 허용 목록으로만 제공하고, 연결이 없을 때 학생 화면이 「연결 없음」·`not_configured`를 성공으로 오해하지 않게 표시하는 것까지입니다.
- `npm run demo`의 응답은 예제 자료이고, `test/`의 검사는 합성 입력입니다. 둘 다 실제 연결 성공이 아닙니다.

## 6. 미완료·미해결 사항

1. 19단계 보안 조치의 실제 집행과 결과 확인(준비되지 않음).
2. SDP 연결로 보는 사용자·기기·세션·업무 앱 판정·보안 기록의 정상 표시(13·14·15단계 실데이터).
3. AI 앱 승인, 연결 점검 성공, 사건 설명 성공(운영 측 권한 준비에 의존).
4. 실제 OSV 조회(허용 패키지 목록이 비어 있음).
5. 13·14·15·16단계 표시 함수의 모의 검사 파일(저장소에 없음).
6. 선택 연결에서 `on-client` 밖의 설정·자격 파일을 읽는 동작(켜지 않음).
7. macOS·Linux, Node.js 24.19.0 외 버전(확인하지 않음. 서버가 `node:sqlite`를 불러오므로 이 모듈이 없는 Node에서는 시작하지 못할 수 있음).

## 7. 데이터 보존·복원 시험 결과

`docs/STUDENT_DATA_RETENTION.md`의 Git 복원 절차를 새 폴더에서 시험했습니다. `git bundle create`로 묶음 파일(671,756바이트)을 만들고, `git bundle verify`를 실행하고, 그 묶음에서 `git clone`한 복원 폴더의 `HEAD`가 재현한 커밋과 같고 추적 파일 수가 65개로 같음을 확인했습니다. 데이터베이스·자격 복원은 시험하지 않았습니다(**미확인**).

## 8. 재현 중 발견한 문제와 수정

- 17단계 모의 검사가 현재 코드에서 실패했습니다. 18단계에서 `renderExplanation`이 근거 연결을 요구하도록 바뀌어 옛 계약의 사건(근거 없음)이 거부되기 때문이며, 코드 결함이 아닙니다. 검사 데이터에 근거·규칙·상태를 추가해 갱신했고, 이 변경은 재현한 커밋에 포함되어 있습니다.
- 앞 단계의 제출·수정 이력은 각각 그 시점 커밋의 판정입니다. 이번 최종 커밋 전체의 성공을 뜻하지 않습니다.
