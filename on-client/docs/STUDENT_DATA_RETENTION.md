# 케셰브 학생 데이터 보존·백업·복원 계획

이 문서는 학생이 직접 작성했습니다. 각 항목은 소스를 읽은 내용인지(**소스 확인**), 이 PC에서 실제로 해 본 것인지(**실행 확인**), 해 보지 않은 것인지(**미확인**)를 구분해 적었습니다.

## 1. 어떤 데이터가 어디에 있나

| 데이터 | 위치 | 보존되나 | 근거 |
|---|---|---|---|
| 학생 소스·문서(`on-client/student/`, `docs/`, `test/`, `README.md`) | 로컬 Git 저장소와 GitHub 원격 `https://github.com/onedotfour88-lgtm/5-stage` | 예. 커밋과 푸시로 보존 | Git 기록 (**실행 확인**) |
| 기본 실행 중 서버 상태(조회 결과, 화면 상태) | 서버 프로세스 메모리 | **아니오.** 종료하면 사라짐 | `src/`, `public/`, `student/`, `vendor/`, `tools/`에서 파일 쓰기(`writeFile`, `appendFile`, `createWriteStream`)와 브라우저 저장소(`localStorage`, `sessionStorage`) 사용 코드를 검색해 찾지 못함 (**소스 확인**) |
| 조치 요청 기록 | 선택 연결(`--alekov-actions`, `--alekov-actions-config`)에서 지정한 **기존 SQLite 데이터베이스 파일**의 추가 테이블 `alekov_action_intents`, `alekov_action_state` 등 | 데이터베이스 파일이 있으면 예. 이 PC에서는 연결하지 않음 | `src/actions/store.mjs` (**소스 확인**, 실행은 **미확인**) |
| 계정 연결 자료·앱 자격 | 선택 연결의 `registryRoot`·`vaultRoot`(프로젝트 밖, 운영자 안내 경로). 자격은 PowerShell 도우미(`tools/app-credentials.ps1`)가 다룸 | 운영 측 관리. **Git에 넣지 않음** | `src/connection/native-context.mjs`, `src/ai/credential-vault.mjs` (**소스 확인**) |
| 환경 설정 값 | 환경변수. 견본은 `on-client/.env.example`(비밀 없음) | 견본만 Git. 실제 값은 Git 제외 | 서버가 `.env`를 읽는 코드가 없고 `process.env`만 읽음 (**소스 확인**) |
| 1~12단계 앱의 자료(메모 등) | 별도 배포·데이터 저장소 | 이번 제출 범위 밖 | 이번 단계에서 확인하지 않음 (**미확인**) |

학생 소스와 문서에는 메모 본문, 비밀번호, 토큰, 키, 인증서, 개인정보를 넣지 않습니다.

## 2. 백업 절차

1. **코드·문서**: 변경을 커밋하고 `git push origin <브랜치>`로 올린 뒤, `git ls-remote origin <브랜치>`의 40자리와 `git rev-parse HEAD`가 같은지 확인합니다. (**실행 확인**: 이번 작업에서 매번 같은지 대조함)
2. **Git 전체 사본**(선택): 저장소 폴더에서 `git bundle create <프로젝트 밖 경로>\keshev.bundle --all`로 묶음 파일을 만들고 `git bundle verify`로 확인합니다. 묶음 파일은 Git 기록만 담고 비밀 파일은 담지 않습니다. (**실행 확인**은 `docs/STUDENT_REPRODUCTION.md`의 복원 시험 참조)
3. **조치 요청 데이터베이스**: 운영자가 지정한 SQLite 파일이며 학생이 만들거나 복사하지 않습니다. 필요하면 서버를 종료한 뒤 운영자 안내에 따라 복사합니다. (**미확인**)
4. **계정 연결·자격**: 백업하지 않습니다. 다른 PC로 옮기지 않고, 분실하거나 초기화되면 운영자에게 다시 발급을 요청합니다.

## 3. 복원 절차

1. 새 빈 폴더에서 `git clone <저장소 주소>` 후 `git checkout <40자리 커밋>`으로 같은 커밋을 받습니다. 묶음 파일이 있다면 `git clone <묶음 파일 경로> <새 폴더>`도 가능합니다.
2. `on-client`에서 `docs/STUDENT_RUNBOOK.md`의 4장 순서로 실행합니다. 설정은 `.env.example`의 이름을 참고해 환경변수로 새로 지정합니다. 기존 폴더의 자격·설정 파일을 복사하지 않습니다.
3. 실행 중이던 화면 상태와 조회 결과는 복원되지 않습니다. 필요하면 화면의 조회 버튼을 직접 다시 누릅니다.

## 4. 제한과 알려진 한계

- 기본 실행은 데이터를 디스크에 남기지 않으므로 서버 상태의 백업·복원 대상이 없습니다.
- 자동 백업 일정, 암호화, 보존 기간, 삭제 정책은 정하지 않았습니다. 운영 데이터(조치 기록 데이터베이스, 계정 연결 자료)의 정책은 운영자 몫입니다.
- 이번에 시험한 복원은 Git 저장소 복원(`git clone`, `git bundle`)뿐입니다. 데이터베이스 백업·복원, 자격 재발급, 1~12단계 앱 자료의 복원은 **미확인**입니다.
- 이 문서는 학생 진술과 소스 읽기에 근거합니다. 서버의 AI 원문 검토가 실행 성공을 증명하는 것은 아닙니다.
